# 北极星 · Web3D 工具引擎演进宪法

**文档等级**：最高。与本文冲突的一切计划、任务卡、代码评审意见，以本文为准。
**修改方式**：只能通过 ADR（见 §5）修改，不接受"顺手改一下"。
**读者**：项目负责人、每一个写代码的 agent、未来接手的人。

---

## 0. 这份文档解决什么问题

技术方案文档回答的是"这一单怎么做"。本文回答的是**"做了三个版本以后，它还是不是同一个东西"**。

单人 + AI 辅助的开发模式有一个特有的失效方式：agent 每次都在局部做出合理决定，六周后你得到一个每处都合理、整体无法演进的系统。防止这件事的唯一办法，是把"不可让渡的约束"写死在代码库里，并且让它可被自动检查。

本文就是那份约束。

---

## 1. 北极星

> **一个可私有化部署的 Web 3D 交互内容底座：把"三维资产 + 交互逻辑"表达为一份可版本化的 JSON 文档，编辑器和播放器只是这份文档的两种视图。**

拆开看三个关键词：

- **底座**，不是项目。判断标准：这次写的代码，有多少比例能原封不动服务下一个客户？低于 60% 就是在做项目。
- **一份 JSON**。判断标准：任何一个功能，如果它需要在 `scene.json` 之外再存一份状态，这个功能的设计就是错的。
- **两种视图**。判断标准：编辑器预览里能跑的交互，播放器里必须逐帧一致；反之亦然。

**唯一北极星指标（NSM）**：
> **在不修改 `@w3/core` 一行代码的前提下，能配置出多少种交付级交互场景。**

这个指标同时约束了商业和技术：它高，说明底座抽象对了，下一个客户是配置工作而非开发工作；它低，说明每来一个需求都要改引擎，产品化的商业逻辑不成立（技术方案 §0.5 的判断）。

## 2. 架构宪法（八条不可让渡）

每一条都标注了**它是怎么被自动检查的**。没有检查手段的约束等于没有约束。

### C1 · 单一真源
所有可持久化状态，有且只有一个来源：`SceneDocument`。运行时状态（当前播放进度、鼠标悬停对象）不进文档；除此之外，任何"记在组件 state 里、记在 ref 里、记在 localStorage 里"的业务状态都是违宪。

> **检查**：任何功能提 PR 时，回答一句话——"这个功能的状态存在文档的哪个字段"。答不上来则打回。

### C2 · Core 框架无关
`@w3/core` 不得依赖 React / Vue / 任何 UI 框架，不得依赖 DOM 之外的浏览器宿主特性。编辑器换框架、播放器裸跑，core 都不动。

> **检查**：`scripts/check-core-purity.mjs` 扫描 `packages/core` 的 `package.json` 依赖与全部 `import` 语句，命中黑名单直接 CI 失败。

### C3 · 编辑器预览与播放器共用同一份 Core
禁止为播放器"简化"一份渲染逻辑，禁止在编辑器里"临时"绕过 core 直接操作 three 对象。技术方案 §1.1 已判定：两边行为不一致是验收时无法辩解的缺陷。

> **检查**：一致性测试（见 §3 的 v0 晋级门槛）——同一份文档 + 同一串输入事件，Editor 预览与 Player 产出的状态轨迹必须逐项相等。

### C4 · Schema 向前兼容
`schemaVersion` 单调递增，每次变更必须同时提交迁移函数。**任何历史版本的已发布快照，必须永远能被当前代码打开。**

> **检查**：`packages/schema/test/fixtures/` 下每个历史版本存一份真实文档样例，回归测试逐个 `migrate → validate`。fixture 只增不改不删。

### C5 · 扩展靠注册表，不靠改引擎
新增一种交互能力 = 向 `actions` / `events` / `conditions` 注册表加一项 + 一段参数 schema。**改到执行器本体，说明抽象漏了，必须先写 ADR。**

> **检查**：PR 若修改 `packages/core/src/eca/executor.ts`，评审必须点名对应的 ADR 编号。

### C6 · 零外部运行时依赖
构建产物中不得出现任何指向外部域名的运行时请求：字体、图标、three.js、Draco decoder、KTX2 transcoder 全部自托管。构建过程本身必须能在断网环境完成。

> **检查**：`scripts/check-no-external.mjs` 扫描 `dist/` 全部文本产物中的 `http://` / `https://` 外链；CI 另跑一次 `--offline` 构建。

### C7 · 存储走抽象层
业务代码不得出现任何具体存储实现（IndexedDB API、S3 SDK、fs、fetch 到某个固定端点）。一切经由 `StorageProvider` 接口。

> **检查**：`scripts/check-storage-abstraction.mjs` 在 `packages/editor` `packages/player` `packages/core` 中扫描 `indexedDB` / `aws-sdk` / `@aws-sdk` / `node:fs` 等标识符。

### C8 · 引擎可脱离 GPU 测试
ECA 引擎、变量系统、条件求值、动作调度，必须能在 Node 里无 WebGL 上下文运行并断言。时间与随机必须可注入（`ctx.now()` / `ctx.wait()`），禁止直接调用 `Date.now()` / `setTimeout`。

> **检查**：`@w3/core` 的 ECA 单测在纯 Node 环境跑，不加载 jsdom canvas；动作注册表覆盖率门槛 100%（每个已注册动作至少一条测试）。

---

**第九条（非技术，但同等重要）**：
### C9 · 稳定 ID 是唯一主键
永远不用 GLB 里的名字、路径、数组下标作为引用键。见 [SCHEMA_SPEC.md](SCHEMA_SPEC.md) §2。
> **检查**：Zod schema 强制 ID 格式；`checkIntegrity()` 在每次保存与发布前跑一遍悬空引用扫描。

## 3. 版本阶梯

七级台阶（v0.5 经 [ADR-0015](adr/0015-插入-v0.5-表现力与体验版本.md) 插入；原"v1 合同交付"经 [ADR-0020](adr/0020-v1-拆成三级台阶.md) 拆成 v1.0 / v1.2 / v1.5 三级）。**每一级有一个"晋级门槛"，门槛不过不许开工下一级**——这是防止底座被功能进度挤压的唯一机械手段。

> **破例只有一条，且是显式的**：G0.5-8（目标机器 benchmark）经 [ADR-0022](adr/0022-G0.5-8-目标机器-benchmark-的挂载方式.md) 改挂为 **v1.0 的出口门槛**，到期版本号 `v1.0`，走的是 §8 的四步。**这是本文迄今唯一一次破例，第三次顺延不许发生**（ADR-0022 代价第 1 条已写死）。

```
v0 底座打穿 → v0.5 表现力与体验 → v1.0 地基与表现力 → v1.2 编排与复用 → v1.5 合同交付 → v2 产品化复用 → v3 私有化/信创
一条垂直切片   对象/光照/材质/媒体   描边雾·爆炸剖切·出图·SDK   flows·pages·模板    后端+验收材料      第二个客户零改引擎   达梦+ARM+离线
```

> **"v1"从此是歧义词**（[ADR-0020](adr/0020-v1-拆成三级台阶.md) 代价第 4 条）：合同语境里它指全部 18 项功能交付完毕（= 本文的 **v1.5**），工程语境里必须补出是哪一级。任何一份文档写"v1"而不补级别，都要当成缺陷登记。

**晋级门槛（本节四条经 [ADR-0023](adr/0023-场景模板从-v2-提前到-v1.2.md) 重写，理由见该条代价第 1 项）**：

| # | 门槛 | 怎么观测 |
|---|---|---|
| **G2-1** | 用**同一份 core 构建产物**交付第二个客户的场景：`packages/core` 的构建产物对照 v1.5 tag **逐字节相等** | `git diff --numstat v1.5..HEAD -- packages/core/src` 为空，**且**两次构建产物的 sha256 相等。报告里必须注明：**产物哈希是证据，"没人改过"不是**（同 [ADR-0026](adr/0026-改写恒真的后端晋级门槛.md) 的判断） |
| **G2-2** | 第二个客户的**全部**需求条目逐条带 §4 分诊结果落账，**Q1 + Q2 合计 ≥ 90%，Q4 = 0** | 一份分诊台账，每条需求一行：需求 / 分诊结果 / 实际改动的文件 / 人日。**分诊结果必须与实际改动文件对账**——标了 Q1 却改了 `packages/core/src`，按 Q4 计，不许事后改标 |
| **G2-3** | **模板作为"配置"的承载力**：第二个客户的起步场景从一个**既有**场景模板开始，交付全程模板**机制**代码 diff 为 0，只允许新增模板**数据**条目 | 机制与数据在文件层面就是分开的（`SCENE_TEMPLATES` / `RULE_TEMPLATES` 是编译进 bundle 的常量数据，见 v1 规划 §1.3"模板存放形态"）。**数据新增行数不设上限，机制改动上限是 0**。这条**不依赖"模板在 v2 才出现"**：它读的是"既有机制够不够用"，不是"机制做没做出来"——机制在 v1.2 就交付了，反而让这条读数比原表述更早、更硬 |
| **G2-4** | 第二个客户从立项到验收的人日 ≤ **v1.0 + v1.2 + v1.5 三级合计**的 40% | 三级合计以 [TASK_BACKLOG_V1.md](TASK_BACKLOG_V1.md) 附录 C 的台账真值为基准（口径写死在验收记录里，不许临场换基准）。**"v1"在这里必须写成三级合计**，否则它是歧义词（[ADR-0020](adr/0020-v1-拆成三级台阶.md) 代价第 4 条） |

> **为什么不是"模板内容够不够用"**：那句话没有判据——"够用"由谁说了算？G2-3 换成了一条能机械对账的等价问题：**够用 = 一行机制代码都不用改**。不够用会当场表现为机制代码出现 diff，而不是表现为一次事后的主观评价。

## 4. 需求分诊流程

**每一个新需求，进来先走这四问。** 这既是技术决策，也是商务定价依据（技术方案 §2 的谈判逻辑）。

```
新需求
  │
  ├─ Q1 现有的 事件/条件/动作 组合能配出来吗？
  │      是 → 【配置】开发量 0，属交付服务，不计变更
  │
  ├─ Q2 只需新增一个 动作/事件/条件 注册项吗？
  │      是 → 【扩展】0.3–1 人日，按变更单价小额计
  │           必须同时补：参数 schema、UI 表单描述、单测、文档一行
  │
  ├─ Q3 需要改 SceneDocument schema 吗？
  │      是 → 【演进】必须写 ADR + 迁移函数 + fixture
  │           schemaVersion +1，人日按实评估
  │
  └─ Q4 需要改 core 架构 / 执行器 / 渲染管线吗？
         是 → 【停】不许直接动手。写 ADR，重新评估预算与工期，
              走变更单。这是所有亏损项目的起点。
```

**分诊结果必须写在需求条目上。** 它同时是给甲方的报价理由：Q1 免费、Q2 小额、Q4 重新计价——理由是结构性的，不是拍脑袋的。

## 5. 决策制度：ADR

任何满足以下之一的决定，必须留一份 ADR（Architecture Decision Record）：

- 修改本文的任何一条；
- 触发分诊 Q3 或 Q4；
- 引入一个新的第三方依赖；
- 在两个都能工作的方案之间做取舍（尤其是"先这样、以后再说"的取舍）。

**位置**：`docs/adr/NNNN-短标题.md`，编号连续，只增不改（要推翻就写新的一条并标 `Supersedes: NNNN`）。

**模板**：

```markdown
# ADR-0007 · 播放器不复用 React

- 状态: Accepted | Superseded by ADR-00XX | Rejected
- 日期: 2026-08-12
- 相关宪法条款: C2, C3

## 背景
（是什么逼我们必须做这个决定，一段话）

## 选项
1. …（代价 / 收益）
2. …

## 决定
（选了哪个，一句话）

## 代价
（我们明确接受的坏处，必须写，不许留空）

## 撤销条件
（什么信号出现时应重新考虑这个决定）
```

**"代价"和"撤销条件"两栏不许留空。** 只写好处的 ADR 是自我说服，不是决策记录。

## 6. 反模式清单

这些是单人 + agent 模式下**必然会发生**的失控方式，提前点名。评审时逐条对照。

| # | 反模式 | 长什么样 | 为什么致命 |
|---|---|---|---|
| A1 | **绕过文档改场景** | 组件里直接 `object3D.position.set(...)` | 违 C1。撤销失效、发布丢失、播放器不一致，三个 bug 一起来 |
| A2 | **播放器分叉** | "播放器不需要这么复杂，我简单写一个" | 违 C3。这是验收时最丢人的缺陷类型 |
| A3 | **执行器长胖** | ECA 执行器里出现 `if (action.type === 'xxx')` | 违 C5。每加一个需求就动引擎，产品化归零 |
| A4 | **schema 无版本变更** | 悄悄加个字段，不动 `schemaVersion` | 违 C4。历史快照静默损坏，最晚在试运行期爆炸 |
| A5 | **名字当主键** | `nodes.find(n => n.name === '泵体')` | 违 C9。改个名字全断（技术方案 R02） |
| A6 | **UI 里做业务判断** | 规则能否执行的逻辑写在 React 组件里 | 违 C8。无法单测，无法生成验收用例 |
| A7 | **CDN 顺手引一下** | `<link href="https://fonts.googleapis…">` | 违 C6。内网部署时白屏，且往往上线当天才发现 |
| A8 | **撤销后补** | "先做功能，undo 最后统一加" | 技术方案 §5.2 已点名：撤销重做必须第二周就位，后补需要重写全部写路径 |
| A9 | **共享材质直改** | 改一个 mesh 的材质，一片全变 | 技术方案 R08。必须 clone-on-write |
| A10 | **fire-and-forget 动作** | 动作不返回 Promise | "播完动画再弹面板"永远做不出来（技术方案 §1.3） |
| A11 | **需求不分诊直接做** | agent 看到需求就开始写 | 免费做掉了本该计价的变更，且往往顺手违了 C5 |
| A12 | **测试留到最后** | "先跑通再补测试" | v0 的晋级门槛全是自动化的，没测试等于没有门槛 |

> **这张表的 "v1" 一列 = v1.0 / v1.2 / v1.5 三级合计口径**（[ADR-0020](adr/0020-v1-拆成三级台阶.md) 代价第 4 条）。收尾时按级各填一次，三行都进 `docs/METRICS.md`。

## 8. 什么时候允许打破宪法

宪法不是不能改，是不能**偷偷**改。允许打破的唯一路径：

1. 写 ADR，说明是哪一条、为什么现在必须破、代价是什么；
2. 在代码里对应位置留 `// CONSTITUTION-EXCEPTION: C5 · ADR-0019 · 到期 v2` 注释；
3. 把检查脚本的白名单加上这一项，**带过期版本号**；
4. 到期未清理，CI 转为失败。

例外必须有到期日。没有到期日的例外，一年后就是新的默认行为。
