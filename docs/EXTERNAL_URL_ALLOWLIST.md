# 模板拼接外部地址 · 豁免表

`scripts/check-no-external.mjs` 的第二遍会扫构建产物里**每一个** `http(s)://` 绝对地址。
其中一类地址是**模板拼出来的**——形如 `` `http://${host}/x` ``，正则只能看到 `http://${host`
这个片段，无法判断它最终指向哪里。

**在 T-209 之前，这一类是无条件放行的**（脚本里一行 `url.includes('${')` 就 continue）。
后果很具体：任何人只要把外部地址写成模板，C6 的守卫就看不见它。这是一个**一行代码宽的洞**，
而 C6 是「内网部署不白屏」这件事的全部机器保证。

现在改成白名单：**只有下表里出现过的前缀才放行，其余一律 fail。**

---

## 怎么填

四列，与 `docs/DEAD_EXPORTS_ALLOWLIST.md` 同一套（`scripts/lib/exemptions.mjs` 读表）：

| 列 | 填什么 |
|---|---|
| `symbol` | **前缀**，逐字取自扫描器的输出。匹配方式是 `startsWith`，所以写得越长越窄 |
| `reason` | 为什么它不会真的发请求。≥10 个汉字，「三方库自带」不算理由——要说清那段代码拿它干什么 |
| `owner` | 到期时由哪张卡负责回读复核 |
| `expires` | 版本阶梯上的一级。**依赖自带的惰性构造也要填**——填的是「复核日」，不是「清理日」 |

> **为什么依赖的代码也要有到期日**：依赖会升级。今天 zod 用 `new URL()` 校验 IPv6，
> 明天它可能换成别的写法，也可能有别的库进来写出同样形状的字符串。
> 一条永不复核的豁免，一年后就是新的默认行为（NORTH_STAR §8）。

## 豁免表

| symbol | reason | owner | expires |
|---|---|---|---|
| `http://[${` | zod 的 ipv6 / cidrv6 校验器用 `new URL()` 解析一个地址来判断它合不合法，构造完就丢，从不发请求 | T-209 | v2 |
