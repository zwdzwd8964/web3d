# ADR-0038 · 编辑器 UI 事件入口的测试范式：逐文件 jsdom，不引测试库

- **状态**：Accepted
- **日期**：2026-08-05
- **任务卡**：T-241（首个落点）· 被 T-242 / T-247 / T-248 / T-251 继承
- **相关**：IMPL_NOTES §4 的 v0.5 M10 教训 · 宪法 C8（无显卡可测）· CLAUDE.md 停下来问人第 3 条（新依赖）

---

## 背景

台账的新纪律与 IMPL_NOTES 里 v0.5 M10 的教训是同一句：

> 凡是卡面出现「点选」「拖动」这类手势的，**验收必须有一条走到 UI 事件入口的测试或
> E2E 步骤**，否则手势层永远是测试盲区。

而这个仓库到今天为止，编辑器一侧**一条渲染 React 组件的测试都没有**：
`packages/editor/vitest.config.ts` 是 `environment: 'node'`，五处源码注释把这个前提写死过
（`rule-editor.test.tsx:18` 那句 "A DOM test would need jsdom" 是其中最明确的一处）。
测试全部停在 lib 层——`effects-edit.test.ts` 直接 `produce()` 调纯 mutator，
`rule-editor.test.tsx` 改用源码文本扫描。

**后果是可复现的**：把面板里任意一个 `onChange` 换成 `() => {}`，全仓一条测试都不会红。
面板与它的 mutator 之间那根线从来没有被任何断言压住过。

T-241 / T-242 / T-247 / T-248 / T-251 五张卡的核心验收都压在这句话上，所以范式要一次定死，
不能每张卡各选一种。

## 决策

**逐文件 `// @vitest-environment jsdom` + `react-dom/client` 的 `createRoot` + React 19 自带的
`act`。不引 `@testing-library/react`。**

三条配套约定：

1. **逐文件开，不改 `vitest.config.ts` 的全局 `environment`。** jsdom 环境的启动成本实测
   约 35 秒/文件，而编辑器现有 24 个测试文件里绝大多数是纯逻辑的，全局打开等于给它们
   全部加一份不需要的开销。
2. **在 `StrictMode` 下渲染。** 编辑器自己跑在 StrictMode 下，而 v0.5 有一个 P0 缺陷正是
   StrictMode 的双次挂载把自动保存永久打死。测试里不开，就测不到那个形状。
3. **只用它测「事件入口到状态写入」这一段**。像素、布局、滚动、真实指针轨迹一律归 E2E。
   jsdom 没有布局引擎，任何依赖尺寸的断言在它上面都是编的。

### 为什么不引 `@testing-library/react`

它是一个新依赖（触发停下来问人第 3 条，要单独批），而它在这里省下的只有几行
`dispatchEvent`。相对地，`jsdom@30.0.1` **早就在 `@w3/editor` 的 devDependencies 里**，
从未被 import 过——这条路零新依赖。

### 为什么不是「一律走 E2E」

E2E 能覆盖手势，但三点不划算：① 每条要起浏览器，反馈从秒级掉到分钟级；② 变异检验要
逐条跑，E2E 的成本会让「每条变异都跑一次」实际上做不到；③ 本批里的 `postfx.spec.ts`
归 T-294 独占，五张卡都往里塞会把一个文件变成五张卡的争用点。

E2E 仍然不可替代的部分保持不变：像素（`colourBuckets`）、真实 GL、跨页面导航。

## 代价

1. **jsdom 环境启动约 35 秒**（实测，`SceneEffectsPanel.test.tsx` 一个文件）。写这类测试
   的卡越多，`pnpm -F @w3/editor test` 越慢。**缓解**：只在真的有手势入口的面板上写，
   逻辑仍然优先落 lib 层单测。
2. **jsdom 不是浏览器**。已知要绕的两处，都在 T-241 的测试里留了注释：
   - 没有 `PointerEvent`，用同名 `MouseEvent` 代替（React 按事件类型名分发，收得到）；
   - 没实现 `setPointerCapture` / `releasePointerCapture`，在被拖拽的元素上打桩。
   每多一处这样的桩，测试与真实浏览器的距离就远一分。**桩超过五处时应当重新评估**。
3. **React 在受控 input 上装了 value setter**，直接赋值会被脏值检查吞掉，必须走
   `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set`。这是一条
   与 React 内部实现耦合的知识，React 换实现时会一起坏。
4. **它证明不了「用户看得见」**。一个 `display: none` 的控件在 jsdom 里照样能被点到。
   涉及可见性的验收仍然必须落 E2E。

## 撤销条件

- 桩的数量超过五处，或者出现「在 jsdom 里绿、在浏览器里坏」的第一个实例——那说明这层
  仿真已经不够，应当把这类断言整体迁到 E2E。
- 或者 `@testing-library/react` 因为别的理由被批准引入——那时把 `dispatchEvent` 的手写
  部分换掉，本 ADR 的其余三条约定不变。
