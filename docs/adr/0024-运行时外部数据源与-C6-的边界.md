# ADR-0024 · 运行时外部数据源与 C6 的边界：URL 进文档，白名单进部署

- 状态: Accepted
- 日期: 2026-08-03
- 相关宪法条款: **C6**（措辞扩写）· **C7**（守卫补洞，净贡献）· C1 · C3 · NORTH_STAR §8（例外三件套）

## 背景

C6 的字面是「构建产物中不得出现任何指向外部域名的运行时请求」。合同措辞（R04 / E1）要求「通过 HTTP/JSON 接口将外部数据字段映射到对象属性或变量」。

这两句话**不是同一句话**：C6 管的是**构建产物**，数据源管的是**文档内容**。但不写下来，第一个读到 C6 的人会认为这个功能违宪，第二个人会认为 C6 已经名存实亡。所以必须有这一条。

### 必须先承认的既成事实

**「我们从不让文档决定外部地址」是错的，v0 就让了。**

`openLink` 在 v0 就已经开了「文档携带任意外部 URL 并由运行时使用」的口子，且**零校验**：

- `packages/core/src/eca/actions/ui.ts:46-49`：`const OpenLinkParams = z.object({ url: z.string().min(1), target: z.enum(['_blank','_self']).default('_blank') })`——除了非空，没有任何约束。
- `packages/core/src/runtime/scene-runtime.ts:926-932`：直接 `globalThis.open(url, target, 'noopener,noreferrer')`。

所以本 ADR **不是开一个新口子，是给一个已经存在了两个版本的口子第一次装上闸门**。把这句话写在背景里，是因为不写的话，本条会被误读成「v1 破了 C6」——实际是 v0 就破了，只是没人登记。

### 必须先承认的第二件事：C6 的自动检查在这条能力上拦不住

`scripts/check-no-external.mjs` **扫不到**「运行时按文档发请求」：

- 它只扫 `dist/`（`:32-38`）；
- Pass 1 匹配 8 种**字面量**取数位置（`:55-64`，其中 fetch 那条是 `/\bfetch\(\s*["'](https?:\/\/[^"']+)["']/i`）；
- Pass 2 扫绝对 URL 并按 8 类白名单豁免（`:74-92`、`:99`）。

URL 在文档 JSON 里、代码形态是 `fetch(变量)` —— **两趟都不命中**。现成活证据：`packages/player/src/main.ts:80` 的 `void fetch(src)` 就在 dist 里躺着，而 `node scripts/check-no-external.mjs` 当前 PASS（`design/datasource.md:609`）。

**因此规划里写「C6 检查会挡住外部数据源」是错的。** 正确的写法是「样板工程的数据源必须是 `mode:'sample'` 或同源，否则黄金路径 E2E 的 `blocked === []` 会红」。

## 选项

1. **不做数据源。** 代价：合同措辞明写的第 17 项交付不全。
2. **白名单进文档**（`meta.allowedHosts` / `dataSources[].allowedHosts`）。代价：**文档自我授权，白名单等于没有**——任何人改一行 JSON 就能让播放器去任意地址取数，而 `.w3p` 是甲方会互相转发的文件；换环境要改所有历史文档。
3. **白名单归部署方，默认仅同源，provider 是唯一取数点，机器判据补进 `check-provider-swap.mjs`**（本条）。
4. **只做 v1.5 的后端代理版。** 代价：「无后端也能完整使用」这个卖点在第 17 项上落空；独立 `.w3p` 双击即演的场景里数据源完全不存在。

## 决定

选 3。一句话概括判据：**URL 是内容**（作者说读哪个接口），**白名单是环境**（运维说允许读哪些域）。

逐条定死，实现期照抄，不许再解释：

| 项 | 裁决 |
|---|---|
| **允许什么** | 运行时按文档声明，向 ① **同源**地址、或 ② **部署方白名单内**的地址，发起 **GET** 请求并解析 **JSON**。仅此。 |
| **禁止什么** | ① 构建产物里出现任何绝对外部 URL（**完全不变**，`check-no-external` 继续零容忍）；② 白名单进文档；③ 白名单进构建产物；④ 默认启用；⑤ 白名单缺失时回退为「允许一切」；⑥ 凭据**值**进文档；⑦ WebSocket / EventSource / 长轮询（v1 不做——退避与生命周期是另一套，形状不同） |
| **谁把关** | `DataSourceProvider` 是**唯一**取数点；`isAllowed(url)` 在发请求之前判。编辑器与播放器**构造同一个 provider、驱动同一个 runner**，差异只有「白名单从哪儿来」（C3） |
| **断网时的行为** | 一律落到 `mode:'sample'`，且在标题上注明「以下是示例数据，不是接口返回」——**这句话不许省**，否则用户会拿着假数据去验收。断网 / 无 provider / 白名单拒绝**三种情况共用同一条回退路径**，于是「断网时怎么办」有一个可演示的答案而不是一段说明 |
| **白名单存在哪** | 四层，全部在宿主侧，**没有一层在文档或 dist 里**：<br>① 默认：**仅同源**（照抄 `packages/player/src/source.ts:23-46` 的三层归一化——剥前导 C0 与空格、反斜杠归一成斜杠、`new URL(x, base).origin` 比对）；<br>② 独立播放器：部署时放在 dist 旁边的 `w3-runtime-config.json`（**同源相对路径**取，绝对 URL 一个都不进构建产物），缺失即退回同源；<br>③ 嵌入 SDK：`mount({ dataSource: { allow: [...] } })`，嵌入页是权威；<br>④ v1.5 后端：服务端代理，浏览器只与同源后端说话，白名单变成项目级设置 |
| **默认关不关** | `enabled` 默认 **false**；白名单默认**仅同源**；provider 缺席时 live 源一律 `blocked` 并回退 sample。**三层默认全部是「关」** |
| **匹配粒度** | **origin 精确匹配**（scheme + host + port），支持 `*.example.internal` 一级通配。路径级白名单会诱使人写正则，而 origin 级已经足够表达「哪台服务器」这个真实问题 |
| **示例地址** | 面板 placeholder / JSDoc / 错误文案里一律用**无 scheme 的相对路径**（`/api/pump/telemetry`）。任何 `http(s)://` 字面量进 dist 都会被 Pass 2 报红 |
| **既有那一处 fetch** | `packages/player/src/main.ts:80` 已由 `resolveSource`（`packages/player/src/source.ts:23-46`）做过同源硬约束。按 `NORTH_STAR.md:283-292` 就地留 `// CONSTITUTION-EXCEPTION: C7 · ADR-0024 · 到期 v1.5（改走 HttpApiProvider）`，并把这一行加进脚本白名单**带过期版本号** |

### 配套的守卫补洞（净贡献，不算代价）

`scripts/check-storage-abstraction.mjs` 的 `FORBIDDEN_IDENTIFIERS`（`:22-29`）今天有 6 条，**一条都不扫网络原语**。这四条 —— `fetch(` / `XMLHttpRequest` / `EventSource` / `WebSocket(` —— 加进 **`scripts/check-provider-swap.mjs`**（由 **T-209** 新建），每条带理由、每次运行打印豁免清单。**网络原语的唯一所有者是 `check-provider-swap.mjs`；`check-storage-abstraction.mjs` 的 `GUARDED` 与 `FORBIDDEN_IDENTIFIERS` 一行不动**——两处维护同一份名单正是 X-29 要避免的，也正是本条自己的撤销条件。这补的正是 C7 宪法原文点名（「`fetch` 到某个固定端点」）而该脚本从来没扫过的那一项——**这条能力让守卫比它到来之前更严，不是更松。**

### 新增集合的指向关系（v0.5 教训：新增被引用对象先列出谁指向它）

`dataSources` 作为顶层集合进 schema v3 之前，必须在 v1.0 的冻结裁决表里逐行写清「**它指向谁 / 谁指向它**」，并把结果落进五个遍历点（zod、迁移、`checkIntegrity`、ID 集合注册表、编辑器快照回滚）。这一步不做，v1.5 第一次写入就会重演 T-176 那三条 blocker——「引用不是从它被指向的地方走过去的」。本 ADR 不代它裁，只把这一步钉死为冻结的前置条件。

### 双向断言（v0.5 教训：只断言「什么都没发生」的测试证明不了守卫生效）

`enabled` 默认 false、`mode` 可以是 sample、provider 可以缺席——**三条路径任何一条成立，「零外部请求」都会通过，与白名单代码写没写完全无关**。所以 E2E 必须**两头都断言**：

1. 先用一个**同源 fixture 端点**证明「它确实发过请求、确实取到了值」；
2. 再把 URL 换成外部域名，证明「这一条被拒了，且拒的理由是白名单」。

`blocked === []` 这个断言之前，必须先有一条断言证明这一轮里数据源真的产出过值。
**变异检验**：把样板工程数据源的 `enabled` 改成 `false`，第一条断言必须转红。

## 代价

明确接受七条：

1. **C6 从「构建产物零外链」扩展成「构建产物零外链 **且** 运行时外链必须经部署方白名单」**——一条更长、更需要人来维护的宪法。宪法越长越容易被读者跳过，这是真实成本。
2. **多一个部署产物 `w3-runtime-config.json`**，忘了放就是「数据源全都不工作」，且报错只在浏览器控制台。部署文档必须写它，而部署文档本身是 v1.5 才交付的。
3. **同一份文档跨环境行为不同**：A 环境能取数，B 环境静默降级。必须在编辑器与播放器都显示「该数据源被部署策略拒绝」，不能静默——但「显示了用户也可能不看」这件事没有工程解法。
4. **独立播放器不支持带鉴权的实时源**，写进《附件C》已知限制。
5. **C6 的自动检查在这条能力上失效**（见背景第二节）。这条能力的合规只能靠完整性检查的 warn 与人工审阅。**这是本 ADR 最大的代价**，写在这里就是为了不让它被忘记：从今天起，「`check:constitution` 全绿」不再等于「没有外部请求」。
6. **`openLink` 的零校验现状本 ADR 不修**，于是仓库里同时存在「有闸门的外部访问」（数据源）与「没闸门的外部访问」（`openLink`）两套，说明力不对称。不修的理由有两条，都写下来供将来推翻：① 给 `openLink` 加校验是**破坏性行为变更**，已发布文档里的合法外链会在升级当天失效；② 威胁模型不同——`openLink` 是「用户主动点击后跳到新标签页」，数据源是「页面自动、周期性地发请求并把结果写进变量」，后者能在用户完全无感的情况下持续外发。**这条不对称必须登记进 IMPL_NOTES，否则下一个人会以为它是疏漏。**
7. **凭据的跨会话存活在 v1.0 无解。** 若数据源密钥要在离线单机版跨会话存活，唯一的浏览器候选是 `localStorage`，而 `check-storage-abstraction.mjs:25` 会直接扫红。**这是一次真正的宪法破例，不能由 agent 拍**——它决定 `auth` 字段在 v1.0 是可用能力还是纯占位。
   > ⚠ **待产品负责人确认**：数据源凭据是否需要在离线单机版跨会话存活。若需要，要额外走一次 §8 破例；若不需要，`auth` 字段在 v1.0 只作为冻结占位，会话内有效、刷新即失。

## 撤销条件

- **甲方 IT 明确拒绝在部署侧维护白名单** → 退到选项 4，数据源只保留 `mode:'sample'`，实时取数整体推给 v1.5 的后端代理。
- **出现第二种需要运行时外链的能力**（AI provider、地图瓦片）→ 说明这不是一个特例而是一类，应把 provider 抽象上提为统一的 `ExternalIoProvider` 并重写本 ADR。
- **`check-provider-swap.mjs` 的白名单条目超过 3 条** → 说明这条守卫正在被绕，而不是在起作用。
- **E-1 那条例外到期（v1.5）而 `main.ts:80` 仍未改走 `HttpApiProvider`** → CI 必须转红。**执行这次转红的是 T-298 交付的 `scripts/check-expiry.mjs`**（v1.0 · M14 · 波次 W3），它按 `NORTH_STAR §8` 第 2 步的注释格式解析 `到期 v1.5`。今天仓库里没有任何脚本读过期版本号（`grep -rl CONSTITUTION-EXCEPTION scripts/` 无输出），因此 **E-1 的例外条款在 T-298 完成之前不生效**；若 T-298 被砍，**本 ADR 的例外条款连带失效**——一条没人能到期的例外，就是 §8 明令禁止的那种例外。
