# ADR-0003 · 类型声明由 tsc 生成，不用 tsup 的 dts

- 状态: Accepted
- 日期: 2026-07-30
- 相关宪法条款: C6

## 背景

MVP 规划 §4 锁定构建工具为 tsup（schema / core / storage）。实测安装得到 TypeScript 7.0.2
（原生编译器）。开启 `dts: true` 时 tsup 崩溃：

```
TypeError: Cannot read properties of undefined (reading 'useCaseSensitiveFileNames')
  at rollup-plugin-dts@6.1.1 ...
```

`rollup-plugin-dts` 尚不支持 TypeScript 7 的编译器 API。

## 选项

1. 把 TypeScript 降到 5.x —— 生态兼容；放弃原生编译器的构建速度，且把一个已发布的主版本
   长期钉在旧线上，迟早要还。
2. 放弃 tsup，全部用 tsc 产出 JS 与 d.ts —— 少一个依赖，对 C6 的离线构建更友好；
   与 §4 锁定的选型不一致。
3. tsup 只产 JS（esbuild 路径不经过 rollup-plugin-dts，工作正常），d.ts 由
   `tsc -p tsconfig.build.json --emitDeclarationOnly` 产出。

## 决定

选 3。`build` 脚本为 `tsup && tsc -p tsconfig.build.json`。§4 的"构建：tsup"字面仍成立，
偏离仅限于声明文件这一步。

## 代价

- 构建分两步，比单命令慢约 1 秒；
- 产物形态混合：JS 是 bundle，d.ts 是逐文件，`dist/` 目录看起来不齐整；
- 若将来换回 tsup dts，需要删掉 tsconfig.build.json 与第二步命令。

## 撤销条件

`rollup-plugin-dts` 支持 TypeScript 7 之后（或项目决定回退到 TS 5.x），改回 `dts: true`
并删除第二步。届时应验证 d.ts 的 re-export 形状未变。
