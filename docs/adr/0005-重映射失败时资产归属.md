# ADR-0005 · 重映射失败的节点，assetId 仍迁移到新资产

- 状态: Accepted
- 日期: 2026-07-30
- 相关宪法条款: C9

## 背景

SCHEMA_SPEC §5.3 对 ambiguous / orphaned 两档的处置写的是"保留原 ref，标 `missing:true`，
UI 让用户选"。"保留原 ref"存在两种读法：
(a) 整个 assetRef 不动，`assetId` 仍指向旧资产；
(b) 只保留 `objectPath` / `objectName` 这两个"要找什么"的坐标，`assetId` 迁到新资产。

## 选项

1. 读法 (a) —— 字面最贴近；后果是一次重映射后场景同时引用新旧两个资产版本，
   运行时要同时加载两份 GLB，且用户在 UI 上看不出为什么。
2. 读法 (b) —— 场景始终只属于一个资产版本；`missing:true` 的语义变成"在新资产里找不到它"，
   与 UI 要展示的候选列表（新资产里的对象）一致。

## 决定

选 (b)。`remapAssetRefs` 对全部五档都把 `assetId` 置为新资产，ambiguous / orphaned 两档
额外置 `missing: true` 并保留原 `objectPath` / `objectName`，供 UI 显示"我们在找什么"。

## 代价

- 与规范原文的一种可能读法不一致，需要人工确认；
- 若用户想"这次先不迁移这个节点"，当前实现没有留出口——只能在报告里人工重指或撤销整次导入。

## 撤销条件

若人工评审确认规范意图是读法 (a)，改回不动 `assetId`，同时必须解决"一个场景引用两个资产版本"
在加载器与体积统计上的连带问题。
