# ADR-0026 · 改写「后端接入没有修改 `@w3/core` 一行」这条恒真门槛

- 状态: Accepted
- 日期: 2026-08-03
- 相关宪法条款: **C7**（存储走抽象层）· NORTH_STAR §3（v1 晋级门槛 `:149-152`）· C2

## 背景

`NORTH_STAR.md:151` 写着 v1 的一条晋级门槛：

> 「后端接入**没有修改 `@w3/core` 一行**——只新增了一个 `HttpApiProvider`（这是对 C7 的实战检验）。」

**这条门槛是恒真命题。**

- `scripts/check-deps-direction.mjs:27` 的 `ALLOWED_EDGES` 里写着 `'@w3/core': ['@w3/schema']` —— `@w3/core` **根本不允许**依赖 `@w3/storage`；
- `CLAUDE.md` 的包边界表把 `@w3/storage` 列进 `@w3/core` 的**禁止出现**项；
- 该脚本的文件头注释（`:13-14`）自己解释了为什么：「core not depending on storage is deliberate: core only knows *hand me an ArrayBuffer*. That is what lets it run under a fake AssetResolver in Node (C8).」

也就是说 **`@w3/core` 里没有一行代码知道 `StorageProvider` 存在**。任何后端设计都会「通过」这条门槛——包括一个把全部业务逻辑搬进编辑器组件、把 provider 抽象彻底架空的设计。它的证明力为零。

这与 E18 复盘里那条教训是同一个形状：**冗余的保障机制会让变异检验集体失灵。** 一条无论如何都会通过的检查，出现在晋级评审的证据栏里，比没有这条检查更危险——它会让人**停止追问**。而 v1.5 的晋级评审，恰恰是 C7 唯一一次被真实压测的时刻。

## 选项

1. **原样保留。**
   - 收益：零成本，宪法不动。
   - 代价：v1.5 晋级评审拿一条恒真命题当 C7 的证据，门槛制度在最需要它的那一次失效。而且这条门槛写着「这是对 C7 的实战检验」——它不只是无用，它是**主动误导**。

2. **删掉。**
   - 收益：不再误导。
   - 代价：丢掉一条本意正确的门槛。它的本意是对的：后端接入不该污染上层。删掉之后 v1.5 的晋级评审就没有任何一条门槛在管这件事。

3. **改写成对 `@w3/editor` + `@w3/player` 的可证明口径**（本条）。

## 决定

选 3。v1.5 的 G1.5-1 由一句话改为**四条断言，前三条是门槛，第四条是度量**：

### ① 装配点唯一 —— 新增 `scripts/check-provider-swap.mjs`，挂进 `pnpm check:constitution`

```
规则 1 · 具体 provider 类名（IndexedDbProvider | MemoryProvider | HttpApiProvider）
        在 packages/editor/src 中出现的文件集合，必须恰好等于
        { packages/editor/src/project/storage-factory.ts }
        —— 不是「≤ 1 个」，是集合相等：
           少了说明装配点被搬走，多了说明泄漏。

规则 2 · 网络原语（fetch( | XMLHttpRequest | new WebSocket | new EventSource |
        navigator.sendBeacon | navigator.onLine）在 packages/{core,editor,player}/src
        中一律禁止，除显式豁免（每条带理由，每次运行打印全部豁免项）。

规则 3 · packages/editor/src 中 import '@w3/storage/http' 的文件集合，
        同样必须恰好等于 { storage-factory.ts }。

规则 4 · e2e/tests/**.spec.ts 中不许出现 'W3_STORAGE' / 'HttpApiProvider' /
        'IndexedDbProvider' 任何一个 —— spec 不许知道自己跑在哪个 provider 上。
```

规则 2 与 [ADR-0024](0024-运行时外部数据源与-C6-的边界.md) 给 `check-provider-swap.mjs` 补的那四条是同一件事的两个落点，实现时合并成一份清单，不要写两遍（`check-storage-abstraction.mjs` 的 `GUARDED` / `FORBIDDEN_IDENTIFIERS` 不动）。

### ② 契约等价

`HttpApiProvider` 通过**逐字相同**的 `describeProviderContract`，对着**真服务器**跑。通过 = drop-in 成立——这句话是 `packages/storage/src/contract.ts:7-14` 文件头自己写的，本门槛只是让它第一次被兑现。

### ③ 行为等价（最有力的一条）

**黄金路径 I 的 spec 文件一个字节不改**，在 CI 里跑两次：`W3_STORAGE=idb` 与 `W3_STORAGE=http`（后者由 E2E harness 起一个真服务器 + 临时库 + 预置一个用户，并在 `storage-factory` 之前用 Playwright 的 `addInitScript` 注入模式）。**两次都绿 = 上层代码对 provider 无感。**

并且这条 E2E 必须顺带断言 `fullRebuildCount === 0`——铁律 11 的报警器在新路径上仍然有效。

### ④ 差异面度量（**是度量，不是门槛**）

`git diff --numstat v1.0..HEAD -- packages/core/src packages/player/src` 的行数。**报告里必须同时打印一句**：

> 「`@w3/core` 的 0 行差异由 `check-deps-direction.mjs` 保证，不构成后端设计的证据；真正的证据是 ① 与 ③。」

不打印这句话，就是把恒真命题当结论用。这一句是本 ADR 全部意义的浓缩，它必须出现在**每次运行的输出里**，而不只是出现在这份文档里——文档没人读，CI 输出有人读。

### 附带补一个今天已存在的盲区

`check-deps-direction.mjs:24-38` 的 `ALLOWED_EDGES` / `DIRS` **硬编码五个包**。v1.5 新增的 `@w3/server` 对它完全不可见——既不会被扫，别人 import 它也不会被判非法边。**这不是「允许」，是「盲区」。**

加第六个包时必须**同时改两张表**（`'@w3/server': ['@w3/schema','@w3/storage']`），并配一条**探针测试**：往 `@w3/server` 里临时写一行 `import 'three'`，守卫必须红。

**没有这条探针，「加进表里」本身也可能是装饰品**——这是 v0.5 那条教训（变异检验）在守卫脚本上的直接应用：一个从来没红过的守卫，和一个不存在的守卫，在证据上是同一个东西。

## 代价

明确接受五条：

1. **修改宪法要走 ADR 流程并通知所有后续 agent。** 旧表述已被 IMPL_NOTES 与勘察记录引用过，会有一段时间口径不一致；引用旧表述的地方要么改，要么加一句「已由 ADR-0026 改写」。

2. **新表述把证明责任压到 E2E 与契约套件上——而这两者必须先被证明是真的在跑。今天不是。**
   `packages/schema/vitest.config.ts:11` 配了 statement coverage ≥ 90% 的门槛，`packages/schema/package.json:25` 有 `"test:cov": "vitest run --coverage"`，但根 `verify`（`package.json:23`）串的是 `pnpm test`，各包的 `test` 脚本都是裸 `vitest run`，CI 不带 `--coverage`——**这条覆盖率门槛从未执行过**。
   若不先修门槛可信度（v1.0 的地基卡），本 ADR 只是把一个**恒真的命题**换成一个**不执行的命题**。两者都是零证明力，后者还更贵。

3. **新门槛比旧门槛贵。** 多一个守卫脚本、多一条双 provider 的 E2E 轨道（黄金路径 I 在 CI 里跑两遍）、多一套对着真服务器跑的契约套件。旧门槛的成本是零，因为它什么都不做。这笔钱是本 ADR 主动要花的。

4. **规则 1 的「集合相等」比「数量上限」严格，重构时会更频繁地转红。** 这是有意的，但它会产生一类「守卫挡路」的摩擦，而第一次遇到的人多半会想去改白名单而不是改代码。守卫的价值恰恰在被绕过的那一刻决定，所以这条摩擦不许用「加豁免」消解。

5. **④ 那句必须打印的话，是一条靠人维护的纪律。** 没有任何机制能保证它不被某次「清理输出噪音」的提交删掉。写在这里，是给那次提交的评审者一个能引用的依据。

## 撤销条件

- **若将来 `@w3/core` 被允许直接依赖存储**（例如为了流式加载超大场景，`check-deps-direction.mjs:27` 因此被改写）→ 旧表述重新变得有意义，届时恢复，本 ADR 作废。
- **`check-provider-swap.mjs` 的豁免条目超过 3 条** → 说明规则 2 正在被绕，应停下来重新设计而不是继续加豁免（同 ADR-0024 的同名判据）。
- **双 provider 的 E2E 因为不稳定被标 `skip` 超过一次** → 门槛 ③ 失效。此时 G1.5-1 退回到只有 ① 与 ②，并**在门槛表里注明降级**——不许静默保留一条已 `skip` 的证据。一条被 skip 的测试出现在证据栏里，与本 ADR 要修的恒真门槛是同一种病。
- **门槛可信度修复（覆盖率真的执行、断网构建真的有人做、`check:constitution` 各项真的扫到位）未在 v1.0 内完成** → 本 ADR 的新门槛不许在 v1.5 的评审里被当作证据使用，因为它依赖的执行面本身没有被验证过。
