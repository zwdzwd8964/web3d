# ADR-0042 · 「没测到」必须与「测出来是 0」长得不一样

- **状态**：Accepted
- **日期**：2026-08-11
- **任务卡**：无（跨卡返修，返修的是 T-277 / T-278 / T-279 / T-281 已交付的四处）
- **相关**：[ADR-0016](0016-逐级加载压力测试的含义.md)（爬坡读数的含义）· [ADR-0022](0022-G0.5-8-目标机器-benchmark-的挂载方式.md)（G0.5-8 挂成 v1.0 出口门槛）· [ADR-0039](0039-剖切面的启用判定用世界可见性.md)（剖切用世界可见性）· [ADR-0040](0040-暂时关闭剖切是渲染开关不是文档编辑.md)（`setSectionsEnabled` 的三态）· 附件A §7 回填规则 1「数字只来自实测」

## 背景

M17 收尾后在本机做了一次端到端试跑（起静态服务器、造一份带爆炸分组与剖切平面的演示包、
真浏览器打开三个页面）。**六个提交全绿、`pnpm verify` 全绿、E2E 全绿**，而试跑一眼看出
四处不对。四处里有三处的共同形状是同一个：

> **一个「没测到」的读数，被印成了一个「测出来是这么多」的读数。**

最刺眼的一份证据：按 `e2e/tests/bench.spec.ts` 自己的环境（`--disable-gpu` SwiftShader +
`?fast=1`）跑 bench 页，报告头三行是

```
[fail] 平均帧率   = 0.0 fps
[pass] P95 帧时间 = 0.0 ms      ← 0 毫秒的帧时间，判「通过」
[pass] 最慢单帧   = 0.0 ms
```

而 `pnpm test:e2e bench` **在这份报告上是绿的**。那条 E2E 是 T-278 写的，它按卡面查了
「行数 ≥ 12」「每行 `data-verdict` 合法」「指标名与实测值非空」——三条全中，因为
`'fail'` 是合法判定、`0.0 fps` 是非空字符串。

### 机制（`measure()` 的两把尺子）

`packages/player/src/bench/main.ts` 的 `measure()` 自 v0（`3d71c05`，T-110）起就是：

```
窗口结束：if (now - started < durationMs) requestAnimationFrame(frame)   ← 墙钟
warmup ：if (warmup > 0) warmup--; else times.push(now - previous)       ← 帧数
```

**两把尺子不同量纲。** 窗口内跑不满 `warmupFrames + 1` 帧时，`times` 是空数组，而
`summariseFrames([])` 返回 `{ fps: 0, p95FrameMs: 0, worstFrameMs: 0, frames: 0 }`。
`frames: 0` 是唯一的区分信号，而 `LightLevel` / `StressLevel` / `ExplodeCost` 三个结构
都只留 `fps` ——**信号在第一层就被丢了**。

归零的临界帧时 = `durationMs / warmupFrames`。这解释了为什么它潜伏了十天：

| 档 | 窗口 / warmup | 归零需要的单帧耗时 |
|---|---|---|
| 主采样（默认） | 6000 / 30 | 200 ms |
| 主采样（`?fast=1`） | **600 / 30** | **20 ms** |
| 灯光（默认） | 900 / 4 | 225 ms |
| 灯光（`?fast=1`） | **200 / 4** | **50 ms** |

而卡顿是必然发生且已知的：three 把灯数与投影灯数放进 shader program 的 cache key，
每次 `off→low`、每次灯数 4→8 都要全场重编译一次，实测单帧 180 ~ 334 ms。900 ms 的窗口
吸收得掉，200 ms 吸收不掉。**T-278 的 `?fast=1` 不是缺陷的成因，是它的扳机。**

### 为什么必须现在修，而不是记进 IMPL_NOTES

T-279 把假 0 的下游从 2 行扩到 6 行（四行「动态灯上限」+「建议出厂默认阴影档」+
「阴影贴图显存（估算）」），**而 T-280 的回填脚本已经把这些行接到了附件A §7**——
一份合同附件。附件A §7 回填规则 1 的第一句是「数字只来自实测」；一个采不到样本的窗口
产出的 `0.0 fps` 不是实测，而现在没有任何一层能把它认出来。

## 决策

### 决策 1 · 采样不足的档报「未测到」，且不参与任何推导

1. `measure()` 加一条**样本下限**：窗口到时若有效样本不足 `MIN_SAMPLES`，把窗口延长，
   最多延长到 `durationMs` 的 3 倍；到硬上限仍不足就如实返回那几个样本。
2. `MIN_SAMPLES = 8`。⚠ **第二轮订正：这个数偏低，而原来写在这里的理由是错的。**
   原文说「8 个样本足以让一次编译卡顿不再主导均值」——算一下不成立：一次 334 ms 的卡顿配
   7 ms 的稳态帧，摊到 fail 线（40 ms/帧）以上需 ≥ 10 个样本，摊到 warn 线（22.2 ms/帧）
   以上需 ≥ 22 个；恰好 8 个时算出 20.9 fps，`isMeasured` 放行而 `shouldStop` 照样截断爬坡。
   另有一处退化：`summariseFrames` 的 p95 索引在 n ≤ 20 时恒等于最大值，**于是「P95 帧时间」
   就是「最慢单帧」**，而 P95 是回填进附件A §7 的四行之一。
   **数字本身没有在第二轮改**：改大会让 `?fast=1` 下大量档变成「未测到」，那个取舍需要真机
   数据。登记在 [IMPL_NOTES](../IMPL_NOTES.md)，随 G0.5-8 结账。
3. `LightLevel` / `StressLevel` / `ExplodeCost` 三个结构一律带上 `frames`，
   `isMeasured(frames)` 是唯一判据。
4. **未测到的档：值写「未测到（样本 N/8）」，`verdict` 判 `warn`，且**
   - 不进 `ceilingFor`（不算上限）；
   - 不进 `recommendShadowDefault`（不参与推荐）；
   - 不进「阴影贴图显存」的选档；
   - **不触发爬坡的提前收摊**——收摊只认真实读数低于 `fpsFail`。
5. `gradeFrames` 同理：主采样样本不足时，三行一起报「未测到」并判 `warn`。

**判据是 `frames >= 8`，不是 `frames > 0`。** 实测过一次 `frames === 1` 的窗口：那一帧
吞了约 357 ms 的卡顿，算出 2.8 fps，照样把整条爬坡截断。只挡 `frames === 0` 治的是表征。

### 决策 2 · 「阴影贴图显存（估算）」取**最贵**的那一档

原实现 `levels.reduce(… l.lights > best.lights …)` 是严格大于 + 插入序遍历，于是永远取
**第一个**达到最大灯数的档——也就是最便宜的 `low`。这与它自己的说明「报的是最重的那一档」
相反，且**在完全没有采样问题的干净跑里也是错的**（实测慢跑 12 档全过，它照样报
「8.0 MB（8 盏 · low）」）。改成按 `estimateShadowMemory(lights, quality)` 取最大值。

### 决策 3 · 剖切档的判据是「装上平面没有」，不是「文档里有没有刀」

`measureSection` 原本问 `doc.nodes.some(n => n.section)`。这只保证「文档里配了刀」，
不保证「这一档量得到东西」——一把 `visible: false` 的刀按 ADR-0039 的世界可见性判定
不装任何裁剪平面，于是产出**三行绿色「通过」的 `0 ms` / `+0 program`**，读者会得出
「剖切几乎免费」这个与事实相反的结论。而带一把关着的刀是**合法文档**，客户送检的资产
照样会这样。

改为：切到「开」之后读回 `renderStats.clipPlanes`，为 0 就报「量不到」，
`verdict` 判 `warn`（送检资产带了刀却量不到，是需要重测的信号，不是通过）。
`gradeSection` 因此要认三种形态：有读数 / 没有刀 / 有刀但都关着。

### 决策 4 · 剖切档挪到爬坡**之前**测 —— ⚠ **已撤回（2026-08-11，对抗式复核证伪）**

`renderStats.programs` 读的是 program 缓存。爬坡跑完之后，开与关两种变体早就都编译进
缓存了，于是 `programsAfterOn - programsBefore` **结构上恒为 0**——那一行观测不到它
声称要观测的东西，而它的说明还写着「开一次剖切等于全场材质重编译一遍」，报告自己打架。
把 `measureSection` 挪到首帧之后、主采样之前，缓存还是冷的，那个差值才有意义。

### 决策 5 · 样板宿主页只 mount 一次，且快速开始带 `.catch`

`samples/host-demo/index.html` 对同一个 `#viewer` 调了两次 `W3Player.mount`（快速开始
切片一次、样板自身接线一次），于是起了**两套完整运行时**：两个 iframe、两份 WebGL2
上下文、两条 rAF 循环，`demo.w3p` 与 `embed-policy.json` 各拉两遍。两个 iframe 竖着排，
第二个整个溢出 540 px 的容器、压在按钮行上，而**四个按钮绑的恰好是溢出到框外的那一个**。

快速开始那段没有 `.catch`，而它与 `docs/EMBED_API.md` §1 逐字锁定——**客户唯一会照抄的
一段，演示的是不处理错误**。两处一起改。

## 第二轮（2026-08-11）· 五个 agent 对抗式复核，判「站不住」

第一轮交付之后派了五路证伪。净效果是正的（`gradeFrames` 三行、逐档明细行、
`recommendShadowDefault`、`shouldStop` 四处确实把两件事分开了），但复核找出 30 条，
其中**两条 blocker**：

### A1（blocker）· 决策 1 只做了半层

`ceilingFor` 只 `filter(isMeasured)` 就 reduce 成 `null`，而 `describeCeiling` 把 `null`
一律印成「不足 1 盏」、判 `fail`；`gradeStress` 同构，印「不足 1 份」。于是**「一档都没
测到」在五条产能结论行上原样长成硬件判决**——而这正是本 ADR 起因那三行 `0.0 fps` 的同一
个缺陷，换了个措辞活下来。同一个文件的 `recommendShadowDefault` 明明为这件事单开了
`anyMeasured` 分支并写了注释，**作者自己的规矩没往上一格走**。

更难堪的是：第一轮新加的 e2e 守卫写的是「值里含『未测到』才查 warn」，这五行不含那三个
字，**正好从新守卫底下走过去**。

修法：`ceilingFor` 返回三态 `Ceiling`（`ok` / `none-passed` / `not-measured`），
`verdictOf` 把 `not-measured` 判 warn。「真的测了、真的一档都不过线」仍判 fail——
那才是硬件结论，两种成因必须分得开。

### C1（blocker）· 账本里有一条是编的

`docs/MUTATIONS.md` 为决策 3 登记的「红 2 条」不可能成立：被变异的那一行在
`measureSection`（`main.ts` 的模块私有函数，**全仓零测试引用**），而它引的两条红打的是
`metrics.ts` 的纯函数 `gradeSection`，喂的是手搓输入。

**一条「声称红、实际绿」的记录，比没有记录更坏**：它让下一个人以为这里有守卫。
修法：判据抽成导出的纯函数 `classifySection` 并配单测，变异才真的红得起来；
原登记行的「实际」订正为「绿」并归入 a 类。

### 其余「现在修」的六条

| B1 | **决策 4 撤回。** 它想让 program 缓存在测剖切时是冷的，而「首屏 · 首帧」为了计时必然更早地按文档态画过一帧——差值仍恒 +0。那一行改报绝对数，并在说明里承认它量不到编译代价 |

## 已裁决（2026-08-11 · 选**乙**）

**`SceneRuntime.setSectionsEnabled(true)` 并不「强制开」。**
`scene-runtime.ts` 里只有 `false` 走 `withoutSections(doc)`，`true` 与 `null` 走同一条
分支——两者逐字等价。而 ADR-0040 的决策段写的是「`true` / `false` 强制开 / 关」。
**实现与已接受的 ADR 不符**，触发「必须停下来问人」第 4、5 条。

编辑器侧（`section-view.ts`）只用 `false` 与 `null`，所以 `true` 这条分支的唯一生产
消费者就是 bench，而 bench 恰恰是唯一指望它「强制开」的调用方。

| 选项 | 做什么 | 代价 |
|---|---|---|
| **甲** 改实现 | 让 `true` 真的强制开：忽略 `node.visible` 装上全部剖切平面 | 绕过 ADR-0039 的世界可见性判据，`livePlanes` 与 picker 的口径要同步跟着走；剖切辅助物的显隐语义要重新定义；至少一张新卡 + 改 ADR-0039 |
| **乙** 改 ADR | 承认 `true` 的语义是「不强制关」，把 ADR-0040 的措辞订正过来 | ADR-0040 的三态叙述失去对称性，`true` 变成一个与 `null` 等价的死值；将来真需要「强制开」时要另开 API |

本 ADR 的四条决策**都不依赖它**：决策 3 用「装上平面没有」作判据，恰好不需要强制开——
装不上就如实说装不上。

### 裁决：**乙**

改 ADR，不改实现。落地三处：

1. `SceneRuntime.setSectionsEnabled` 的签名收窄成 `false | null`，`true` 从 API 面上
   消失。**一个看起来有意义的死值，比没有这个值更坏。**
2. [ADR-0040](0040-暂时关闭剖切是渲染开关不是文档编辑.md) 的决策段加一段订正，
   并把「两个强制值三态」改成「一个强制值两态」。
3. bench 的 `measureSection` 把那次 `setSectionsEnabled(true)` 改成 `null`——写成
   `null` 之后，那一行说的是它真正在做的事：**交还给文档**。这一档因此量的是「按文档态
   该切的时候，切与不切差多少」，而那正是用户点那一下会遇到的事。

选乙而不是甲的理由：甲要绕过 ADR-0039 的世界可见性判据（而「刀的开关就是 `node.visible`」
是 T-243「零新增动作」成本论证的全部依据），并让「哪些平面是活的」有两个所有者——正是
ADR-0040 代价 2 自己点名的那种结构。而**没有人需要它**。

## 代价

1. **bench 变慢，而且慢的幅度取决于机器。** 延长窗口的上限是 3 倍，最坏一轮
   `?fast=1` 从今天的 ~5 秒涨到十几秒。`e2e/tests/bench.spec.ts` 的 `BUDGET_MS`
   是 30 秒，要一并复核——**而这正是那条断言存在的意义**：它本来就该在「某档忘了收摊」
   时红。
2. **报告里会出现「未测到」的行，而客户会问为什么。** 这是刻意的：一份写着「未测到」
   的报告能被信任，一份写着 `0.0 fps ✅ 通过` 的不能。
   ⚠ **第二轮订正**：这里原本写「本 ADR 不改回填脚本 …… 登记为待办」，而复核指出那是
   把缺陷链停在了终点前一步——脚本会把「未测到（样本 3/8）」写进「目标值」列并盖上
   `[实测]` 章，按 §7 回填规则 5 占掉这一档唯一的实测名额。第二轮补了拒绝（A4），
   理由与拒绝软渲报告完全相同。
3. **`MIN_SAMPLES = 8` 是拍的，不是测的。** 与设备像素比封顶 / 剖切平面上限 / 描边
   预设上限同类（NORTH_STAR §8 的破例清单，到期版本号 `v1.0`）。碰到它时不要当成
   实测结论引用。
4. ~~决策 4 改变了 bench 的档序~~ —— **决策 4 已在第二轮撤回，这条代价随之作废。**
   撤回后档序还原，「几何体 / 着色器」那一行不再把 bench 自己为测量而编译的 clip=0 变体
   算进客户模型（实测 5 → 9 的污染消失）。

## 撤销条件

- **决策 1**：出现一台机器，在 3 倍硬上限内仍然凑不满 8 个样本，而它确实是目标机器
  ——那说明这台机器跑不动这个场景，届时该改的是「未测到」的文案（要说清是机器太慢
  还是采样太短），不是放宽 `MIN_SAMPLES`。
- **决策 3**：若将来「未决」一节按选项**甲**裁决（`true` 真的强制开），本决策的判据
  仍然成立——它问的是结果（装上平面没有）而不是意图。
- **决策 4 已撤回**，无需撤销条件。若将来真要量「开剖切多花了多少编译时间」，正确的
  做法不是调档序，而是**在首帧之前先按 `withoutSections` 画一帧建立基线**——那会改变
  「首屏 · 首帧」的语义，属于另一张卡。
- **决策 5**：若样板页将来要演示「一页嵌两个播放器」，本决策整条失效——但那时
  `mount()` 应当先长出「一个容器一个播放器」的显式约束，而不是靠样板页自觉。
