# ADR-0014 · 共用播放会话放在 `@w3/core`，而非任务卡指定的 `@w3/editor`

- **状态**：已接受（**但需人工确认**，见下）
- **日期**：2026-07-31
- **相关**：T-102 · 宪法 C3 · MVP_V0 §3 依赖方向

---

## 背景

T-102 卡片写明：

> **独占** `packages/editor/src/preview/preview-session.ts`
> **做** 抽出 `createPlaybackSession(doc, ctx)` 供两侧共用。
> **编辑器预览与 Player 走完全相同的初始化与事件路径**（宪法 C3）

卡片同时要求两件事，而在指定位置上这两件事互相排斥：

1. 函数放在 `packages/editor/`；
2. 播放器也调用它。

而 MVP_V0 §3 的依赖方向图里，`@w3/player` **不依赖** `@w3/editor`，两者是并列的下游。
`check-deps-direction.mjs` 会机械拦下这条反向边。

在指定位置上，只剩两种走法，都很糟：

- 播放器依赖编辑器 —— 直接违反依赖方向，且播放器会把整个 React 编辑器拖进它的
  400KB 体积预算；
- 播放器自己复制一份 —— **这正是 T-102 存在的原因**。两份「完全相同的初始化路径」
  会在第一次有人改动其中一侧时分叉，而 C3 分叉恰恰是 parity 测试要抓的东西。

## 决策

放在 `packages/core/src/runtime/playback-session.ts`。

职责边界按「是否影响行为」切：

| 归共用函数 | 归宿主 |
|---|---|
| 引擎构造与 attach | 画布 |
| 事件接线的**顺序** | 资产解析器 |
| `sceneReady` 的时机 | 渲染器 |
| 点击 / 悬停 / 热点的语义 | 时钟来源 |
| 悬停 enter/leave 状态机 | 指针拾取（需要画布） |
| 停止时的中止与重置**顺序** | 网格等编辑器装饰 |

右列的差异正是 parity 要证明「不泄漏到行为」的东西，所以它们留在宿主是对的，
不是妥协。

## 代价

- **与任务卡的字面要求不一致。** 按 CLAUDE.md「什么时候必须停下来问人」第 5 条
  （任务卡验收标准与 SPEC 冲突），这本应是**停工问人**项，而不是自行写 ADR 放行。
  已在交付报告里单独列出请人工确认，未自行销案。
- `@w3/core` 多了一个面向宿主的编排层。它不引入任何新依赖，也不违反 C2
  （无 React、无 DOM，除渲染器本身），但确实让 core 的职责边界比原先宽了一点。
- 卡片指定的 `preview-session.ts` 不存在；编辑器侧对应的是
  `packages/editor/src/preview/controller.ts`，只保留编辑器专属职责（退出还原编辑态）。

## 撤销条件

1. **人工评审认为应当严格照卡片走** —— 那么需要同时给出「播放器如何在不依赖编辑器的
   前提下复用同一路径」的方案，或者接受两份实现并放弃 parity 的意义；
2. 依赖方向图本身变更（例如引入一个两者共同依赖的 `@w3/host` 包）—— 届时这个函数
   应当搬过去，core 恢复原先的边界。

## 未采纳的方案

| 方案 | 不采纳的理由 |
|---|---|
| 播放器依赖编辑器 | 违反依赖方向；把 React 拖进 400KB 预算 |
| 各写一份 | T-102 存在的全部意义就是消除这件事 |
| 新建 `@w3/host` 包 | 为一个 160 行的函数新增一个包；规划里没有这个包，需要更大的决策 |
