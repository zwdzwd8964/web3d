# ADR-0015 · 版本阶梯插入 v0.5「表现力与体验」

- 状态: Accepted
- 日期: 2026-07-31
- 相关宪法条款: NORTH_STAR §3（版本阶梯）、C4、C5、C6

## 背景

v0 的七条晋级门槛已过六条，唯一未过的 G0-7（benchmark 目标机器实测）缺的不是代码，
是一次去客户机器上跑的机会。与此同时，产品负责人明确了下一步优先级：对象库与放置体验、
光照效果、材质纹理与多媒体库——这些在原阶梯里属于 v1，但 v1 同时捆绑后端、权限、
出图与全套合同验收材料。摆在面前的矛盾是：按原阶梯，「门槛不过不许开工下一级」会让
团队为等一次外部实测而空转；直接开工 v1 则等于无视门槛制度，而门槛制度是这个项目
防止底座被功能进度挤压的唯一机械手段。

## 选项

1. **等 G0-7 完成后按原阶梯开工 v1。** 收益：制度零例外。代价：进度阻塞在一个
   纯外部依赖上；且 v1 范围过大（后端 + 8 项功能），一次吞下违背 v0 用垂直切片
   验证架构的成功经验。
2. **把 v1 中不依赖后端的"表现力"块拆出，插入 v0.5，G0-7 义务顺延为 v0.5 门槛。**
   收益：进度不空转；表现力四件套（对象/光照/材质/媒体）恰好是对 C4（一次迁移）
   与 C5（注册表扩展）的第一次实战检验，NSM 第一次有了真实读数。代价见下。
3. **无视门槛直接做。** 不可接受：例外一旦无到期日，一年后就是新的默认行为
   （NORTH_STAR §8 原话）。

## 决定

选 2。阶梯变为 v0 → **v0.5** → v1 → v2 → v3；v0.5 的范围与门槛见
[MVP_V0_5_进化规划.md](../MVP_V0_5_进化规划.md)；G0-7 顺延为 v0.5 的 G0.5-8，
v0.5 晋级 v1 前必须补上。

## 代价

1. 阶梯多一级，管理成本增加；v1 的「模型库与材质库」「多媒体」两项被提前以本地版
   消化，v1 开工时必须重新核对范围，避免与甲方重复计价或漏计后端化工作量。
2. G0-7 的实测欠账继续存在，而且 v0.5 引入的实时阴影与 HDRI 会让性能达标**更难**
   而不是更容易——欠账在放大，不是在消失。
3. `schemaVersion` 提前消耗一个版本号与一条迁移链；fixture 目录多一代需要永久维护。

## 撤销条件

- v0.5 开工后若目标机器实测完成且严重不达标（如中档阴影下帧率 < 30fps），应立即
  停止表现力扩张，转入性能整改——继续加灯光只会扩大返工面。
- 若合同要求 v1 提前启动，v0.5 未完成部分并入 v1 backlog 并重新走 §4 分诊，
  本 ADR 标记 Superseded。
