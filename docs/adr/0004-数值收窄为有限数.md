# ADR-0004 · Vec3 / Quat 等数值字段收窄为有限数

- 状态: Accepted
- 日期: 2026-07-30
- 相关宪法条款: C4

## 背景

SCHEMA_SPEC §4 写的是 `z.tuple([z.number(), z.number(), z.number()])`。同一份规范 §0.5 又要求
文档必须能 `JSON.stringify → JSON.parse` 往返后完全相等。这两条互相矛盾：`NaN` 与 `Infinity`
是合法的 `number`，但 JSON 序列化后变成 `null`，往返即失真。

NaN 进入 transform 的现实后果是 three.js 场景图里出现无效矩阵，物体从视口消失且无报错——
排查成本极高。

## 选项

1. 照字面用 `z.number()` —— 与规范逐字一致；把一个已知会静默损坏文档的输入放进来。
2. 收窄为 `z.number().finite()` —— 接受的文档集合严格变小，不会拒绝任何合法文档；
   与规范字面有一处差异。
3. 保持 `z.number()`，另在 checkIntegrity 里查 —— 校验分散，且 validate 通过的文档仍可能是坏的。

## 决定

选 2。`primitives.ts` 内部统一使用 `z.number().finite()`，并在文件头注明理由。

## 代价

- 与 SCHEMA_SPEC 的字面文本有一处可见差异，后续维护者对照时会短暂困惑（已在代码注释中说明）；
- 若将来真有字段需要表达"无穷远"（例如相机 far 为 Infinity），需单独放开。

## 撤销条件

若规范作者认为应严格照抄，改回 `z.number()`，同时必须在 §0.5 的往返测试里显式排除 NaN，
并接受 transform 可能被写入 NaN 的风险。
