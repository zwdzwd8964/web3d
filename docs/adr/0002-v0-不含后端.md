# ADR-0002 · v0 不含后端

- 状态: Accepted
- 日期: 2026-07-30
- 相关宪法条款: C7

## 背景

技术方案 §5.1 估算 45 人日、实际可用约 32 个工作日，缺口 40%。后端（认证/权限/项目/资产/版本/
审计）估 5 人日，且它对"底座抽象是否正确"这个 v0 唯一要回答的问题没有贡献。

## 选项

1. v0 就做后端 —— 交付形态完整；吃掉 5 人日，且底座尚未定型时写的 API 大概率要重写。
2. v0 纯前端 + 本地存储，不留抽象 —— 最快；v1 接后端时业务代码全面开刀，等于重做一遍。
3. v0 纯前端 + `StorageProvider` 抽象，只实现 IndexedDB —— 省 5 人日，且 v1 接后端时新增一个
   `HttpApiProvider` 即可，"业务代码零改动"本身成为 v1 对 C7 的验收项。

## 决定

选 3。`@w3/storage` 定义接口并提供 MemoryProvider / IndexedDbProvider 两个实现，
两者跑同一套 `describeProviderContract` 契约测试。

## 代价

- v0 无法演示多用户、权限、审计，甲方看到的是单机形态；
- 契约测试是额外投入，且 IndexedDB 实现在纯 Node 下跑不了（见 IMPL_NOTES 的未验证项）；
- 数据只在浏览器本地，换机器即丢失，试用期需明确告知。

## 撤销条件

若甲方在 v0 阶段就要求多人查看同一项目，或明确要求服务端留存，则本决定失效，
需在 v0 内插入一个最小 `HttpApiProvider` 并重新排期——但仍不改业务代码，那正是这层抽象的意义。
