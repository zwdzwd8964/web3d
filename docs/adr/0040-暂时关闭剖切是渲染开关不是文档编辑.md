# ADR-0040 · 「暂时关闭剖切」是一个渲染开关，不是一次文档编辑

- **状态**：Accepted
- **日期**：2026-08-05
- **任务卡**：T-251
- **相关**：X-03 / [T-243](../TASK_BACKLOG_V1.md)（剖切「启停复用 `node.visible`，零新增动作」）· 铁律 1（状态只进文档，运行时瞬态是唯一例外）· D29（爆炸系数是瞬态）· T-235 的 `setPostFxEnabled`

---

## 背景

T-243 的整个成本论证建立在一句话上：**剖切的启停复用 `node.visible`，零新增动作**。
于是它自动继承变换手柄、层级树、撤销、`setVisible` 动作、退出预览还原——功能成本从
5 个 core 文件降到 1 个。

T-251 的卡面要求一个「暂时关闭剖切」的会话开关，并明写它**不进文档、不进 localStorage**。
这两句话直接冲突：不进文档就不能走 `commit` 改 `node.visible`，于是它必须是一个
**新的 core 运行时 API**——而那是 T-243 明确不打算付的成本，且没有任何一张卡认领它。

## 决策

**加一个运行时级 override：`SceneRuntime.setSectionsEnabled(enabled: false | null)`。**

- `false` 暂时关掉全部剖切，`null` 交还给文档（`node.visible`）。
- 状态是运行时瞬态，与「当前播放进度」「爆炸系数」同类——铁律 1 明写的那条例外。
- **形状抄 `setPostFxEnabled`**（T-235）。同一个问题在这个仓库里已经出现过一次，
  答案就该长得一样——但**只抄到「有一个 override + null 交还」为止**，见下面的订正。

> ### ⚠ 订正（2026-08-11 · ADR-0042 未决项裁决为**乙**）
>
> 这一段原本写的是「`true` / `false` **强制开 / 关**，`null` 交还给文档」，签名是
> `boolean | null`。**那是错的，而且从第一天起就是错的**：实现里只有 `false` 走
> `withoutSections(doc)`，`true` 与 `null` 走同一条分支、逐字等价。
> **「强制开」从来没有存在过。**
>
> 缺口能活这么久，是因为编辑器侧（`section-view.ts`）只用 `false` 与 `null`，
> 而 `true` 的唯一生产消费者是 v1.0 才出现的 bench——恰好也是唯一指望它「强制开」的
> 调用方。ADR-0042 的对抗式复核把它翻了出来。
>
> **裁决：改 ADR，不改实现**（选项乙）。理由三条：
>
> 1. 「强制开」要绕过 [ADR-0039](0039-剖切面的启用判定用世界可见性.md) 的世界可见性
>    判据，而「刀的开关就是 `node.visible`」正是 T-243「零新增动作」成本论证的全部依据；
> 2. 它会让「此刻哪些平面是活的」有**两个所有者**——正是本 ADR 代价 2 自己点名的那种
>    结构；
> 3. **没有人需要它。** bench 要的是「装上平面没有」，装不上就如实说装不上
>    （ADR-0042 决策 3），恰好不需要强制开。
>
> 签名随之收窄成 `false | null`：**一个看起来有意义的死值，比没有这个值更坏**——
> 它让调用方以为自己拿到了一个开关。将来真需要「强制开」，那是一次带 ADR 的新增，
> 不是往这里悄悄塞回一个 `true`。

### 为什么这不算推翻 T-243

T-243 说的是**启停**（这把刀开着还是关着，属于文档内容）复用 `node.visible`，那一条不变：
用户在层级树里隐藏一个剖切面，仍然是一次 commit、进撤销栈、发布出去也是关的。

本 ADR 加的是**另一件事**：「我现在想看看没被切开的样子」。它与「把刀关掉」在结果上一样，
在语义上完全不同——

| | 改 `node.visible` | `setSectionsEnabled(false)` |
|---|---|---|
| 进撤销栈 | 是 | **否** |
| 发布出去 | 跟着走 | **不跟** |
| 退出编辑器 | 保留 | **丢弃** |
| 用户的心智 | 「这把刀我不要了」 | 「我先看看原样」 |

把后者做成前者，会让「看一眼」进撤销栈——用户 Ctrl+Z 撤销掉的是一次「看」，
正是 D29 拒绝把爆炸系数写进文档时逐字给出的那个理由。

### 为什么是全局开关而不是逐面开关

逐面开关等于给每个剖切面各存一份瞬态，而它们与文档里的 `visible` 会形成一张二维真值表
（文档开/关 × 会话开/关），用户看不出画面上那把刀为什么不切。全局一个「暂时关掉全部剖切」
是一次可以整体撤销的动作，也是这个功能唯一被反复要求的形态（「让我看看完整的」）。

## 代价

1. **core 多了一个公共 API，而 T-243 的成本论证里没有它。** 那句「零新增动作」在
   *ECA 动作* 这一层仍然成立（这不是一个动作，规则里调不到它），但「1 个 core 文件」
   这个数字要改成 2。如实记在这里。
2. **两个来源决定同一件事**（文档的 `visible` 与会话 override），这类结构在这个仓库里
   出过事：v0.5 的「工具条上写着 0.5、拖出来却是自由」正是两个所有者。缓解办法与
   `setPostFxEnabled` 相同——**override 只有 `null` 与两个强制值三态，且 `null` 是默认**，
   所以「没人动过它」与「有人强制过它」在代码里分得开。
3. **它不进 localStorage，所以刷新即丢。** 用户可能觉得「我明明关掉了」。这是刻意的：
   一个跨会话记住的「剖切被关掉」会让下次打开时画面与文档不符，而层级树里那把刀
   看起来是开着的。

## 撤销条件

- 出现第二个「我先看看不带 X 的样子」的需求（例如「暂时关掉全部爆炸」），且两者要能
  同时生效——那时应当把这类会话 override 收成一张统一的表（`viewOverrides`），
  而不是各写一个方法。届时 `setPostFxEnabled` / `setSectionsEnabled` 一起并进去。
- 或者用户反馈显示他们期望它跨会话保留——那说明它其实是一项**偏好**（与吸附同类），
  该进 localStorage，本 ADR 的第 3 条代价随之失效。
