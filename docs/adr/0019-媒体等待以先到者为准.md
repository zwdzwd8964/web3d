# ADR-0019 · 媒体等待以「先到者为准」，为此给 RuntimeContext 加一个方法

- **状态**：已接受
- **日期**：2026-08-02
- **任务卡**：T-186
- **相关**：[D19](../MVP_V0_5_进化规划.md#d19-媒体时长进文档播放语义与动画对齐) · [ECA_SPEC §7](../ECA_SPEC.md)

---

## 背景

D19 写的是：

> 真实环境听 `ended`（**以先到者为准**），headless 走 `ctx.wait(durationS)`。

实现只做了后半句。`playMedia` 的 `await: true` 分支只有一行
`await ctx.wait(durationS * 1000, signal)`，而 `MediaBus.waitForEnd` 写好了、测过了、
**零个生产调用者**——它是一段完整实现但从未接进任何路径的代码（T-176 审查所得）。

后果是：`durationS` 是导入时浏览器报的数，和实际播放长度可以差出几百毫秒到几秒
（可变码率、容器里的填充、浏览器之间对 `duration` 的口径不一致）。于是「响完铃再弹面板」
要么早弹（面板压着还在响的最后一秒），要么晚弹（用户盯着静止画面等）。
**这正是 D19 要求「先到者为准」的原因**，不是冗余。

## 问题

动作跑在 ECA 里，铁律 6 禁止它碰真实时间和 DOM，所以它拿不到 `HTMLMediaElement`，
也就听不到 `ended`。而 `RuntimeContext` 是动作与运行时之间唯一的门。

想让动作参与这场竞速，只有三条路：

1. 动作里直接摸媒体元素 —— 违反铁律 6，且 headless 单测立刻挂；
2. 让 `playMedia(id)` 在 `await` 模式下不再「开始播放即 resolve」，改成播完再 resolve ——
   改的是 ECA_SPEC 已冻结的语义，而且把「等待」从动作挪回运行时，正好和 D19
   「等到播完是**动作**的事」相反；
3. 给 `RuntimeContext` 加一个方法，把「这个片段播完了」表达成动作能 await 的东西。

## 决定

**走第 3 条：`RuntimeContext` 增加 `waitForMediaEnd(id, signal?): Promise<void>`。**

```ts
// 动作里
await Promise.race([ctx.wait(durationS * 1000, signal), ctx.waitForMediaEnd(p.mediaId, signal)])
```

两侧实现：

| 实现 | 行为 | 理由 |
|---|---|---|
| `SceneRuntime` | 委托 `MediaBus.waitForEnd`，监听真实 `ended` | 真实环境听得到 |
| `HeadlessRuntime` | 返回一个**永不 resolve**、但响应 abort 的 promise | 无 GPU 无 DOM 环境观测不到「播完」，诚实的答案是「我这边永远不会先到」，于是计时器一侧必然获胜——正好是 D19 对 headless 的要求 |

`waitForEnd` 在片段并未播放时立即 resolve（浏览器拒绝自动播放，V3）。这是对的：
什么都没在响，就不该让序列干等一个 `durationS`。

## 代价

1. **这是一次 ECA_SPEC 接口扩张。** `RuntimeContext` 从「动作能做什么」多了一项
   「动作能等什么」。已同步回写 ECA_SPEC §7 的接口清单。
2. **两侧实现必须继续同构。** 已有的 `RuntimeContext` 契约测试自动覆盖这一条——
   它是遍历接口的，新方法漏实现会当场红。
3. **headless 那个 promise 永不 settle。** 竞速中被丢弃后由 GC 回收；abort 时会 reject，
   所以不会把取消路径挂住。代价是它在被丢弃前一直挂着一个 abort 监听器，
   量级是「每个 await 的 playMedia 一个」，可忽略。
4. **多了一条时序上的岔路**：真实环境里两侧都可能先到，测试必须两侧各测一次，
   否则又是一条只覆盖了一半的绿灯。

## 撤销条件

如果出现「`ended` 在某些浏览器上不可靠地不触发」，导致真实环境反而比 headless 更晚结束，
则退回只用 `ctx.wait(durationS)`，删掉这个方法与 `MediaBus.waitForEnd`，
并在 D19 里把「先到者为准」改成「以 `durationS` 为准」——**连同理由一起改**，
而不是留一条实现不了的规范。
