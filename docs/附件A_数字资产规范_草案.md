# 附件A · 数字资产规范（草案）

> **性质**：合同附件草案。本文件的用途是把「性能验收」变成一件双方事先能对齐的事——
> 交付方按此规范提供模型，我方按此规范承诺表现。**超出本规范的资产，其运行表现不作为验收依据。**
>
> **来源约定**：每一行数值都标注来源。三类：
> - `[代码]` —— 来自 `packages/core/src/assets/policy.ts`，导入体检**当场机械执行**，改一个数就要改这份文档
> - `[规范]` —— 来自 [SCHEMA_SPEC.md](SCHEMA_SPEC.md) / [MVP_V0_孵化规划.md](MVP_V0_孵化规划.md) 的明文条款
> - `[待实测]` —— **尚无实测来源**，需在目标机器上跑 [BENCHMARK.md](BENCHMARK.md) 后回填
>
> **本草案不含任何拍脑袋的数字。** 凡是没有来源的，标了 `[待实测]` 并留空，没有用估计值填充。
>
> 对应任务卡 T-113 · 技术方案 R01 · 合同 §6.3

---

## 0. 为什么需要这份文档

技术方案 R01 把它说清楚了：**客户的 CAD 导出件是唯一没有任何架构能解决的问题。**
一个 800 万面、带 60 张 4K 贴图的装配体，在任何引擎里都会卡；届时讨论的不会是
「这个模型超标了」，而是「你们的产品性能不行」。

这份附件把那场讨论提前到签约前。它同时是技术保险和商务保险。

## 1. 文件格式与交付方式

| 项 | 要求 | 来源 |
|---|---|---|
| 格式 | **glTF 2.0 二进制（`.glb`）**，单文件自包含 | `[规范]` MVP_V0 §1.2 v0 只支持 glTF/GLB |
| 几何压缩 | 允许 Draco | `[代码]` 解码器已自托管于 `vendor/draco/`，离线可用 |

| 交付方式 | 单个 `.glb` 文件；多个部件可分多个文件分批导入 | `[代码]` 导入按内容哈希去重，同一文件重复提交不额外占用存储 |

## 2. 体量上限（导入时机械执行）

以下阈值由 `DEFAULT_POLICY` 逐项检查，超标当场在导入报告里逐项标出并给出处置建议。
**超标仍可导入**（不阻断工作），但其性能表现不作为验收依据。

| 指标 | 上限 | 接近上限（黄灯） | 来源 |
|---|---|---|---|
| 单文件大小 | **60 MB** | 48 MB | `[代码]` `DEFAULT_POLICY.maxBytes` |
| 三角面数 | **300,000** | 240,000 | `[代码]` `DEFAULT_POLICY.maxTriangles` |
| 材质数量 | **60** | 48 | `[代码]` `DEFAULT_POLICY.maxMaterials` |
| 贴图数量 | **40** | 32 | `[代码]` `DEFAULT_POLICY.maxTextures` |
| 贴图解码后显存 | **128 MB** | 102 MB | `[代码]` `DEFAULT_POLICY.maxTextureBytes` |
| 单张贴图边长 | **2048 px** | 1638 px | `[代码]` `DEFAULT_POLICY.maxTextureSize` |
| 节点数量 | **5,000** | 4,000 | `[代码]` `DEFAULT_POLICY.maxNodes` |

黄灯阈值 = 上限 × **0.8**（`[代码]` `WARN_RATIO`）。

> **贴图那一行说的是解码后显存，不是文件大小。** 一张 2048×2048 的 PNG 可能只有 3 MB，
> 上传到 GPU 后占 16 MB（RGBA8）到 21 MB（含 mip 链）。耗尽显存的是后者。

### 尚无来源的一项

| 指标 | 状态 | 说明 |
|---|---|---|
| 每帧 draw call 上限 | `[待实测]` 当前经验值 1,200 | 导入体检统计的是材质数与网格数，不是绘制批次；真实上限取决于目标机器的 GPU 与驱动。**在目标机器跑过 benchmark 前，此数值不进合同。** |

## 3. 坐标系、单位与朝向

| 项 | 要求 | 来源 |
|---|---|---|
| 单位 | **米（m）**。若交付件为毫米或厘米，导入时声明源单位，系统按比例归一化 | `[代码]` `computeNormalization`，`UNIT_SCALE` |
| 上方向 | **Y 轴向上**。Z-up 的交付件（多数 CAD 默认）在导入时声明，系统绕 X 轴 −90° 校正 | `[代码]` `computeNormalization`，`axisRotated` |
| 原点 | 建议置于装配体的**几何中心或安装基准面**，不要留在远离模型的世界原点 | `[规范]` 无硬性要求，但原点远离模型会让「取景」把镜头拉得很远 |
| 变换 | 允许节点自带变换；不要求导出前 freeze | `[代码]` 实例化时逐节点保留 TRS |

> 归一化是**一次性**的：导入时把矩阵烘进根节点，此后文档里的坐标就是米、就是 Y-up。
> 同一份资产的第二次上传若声明了不同的源单位，会得到不同的比例——**同一批资产请统一声明。**

## 4. 命名与层级

这一节直接影响「二次上传后配置是否还在」，是全篇商务风险最高的一节。

| 项 | 要求 | 来源 |
|---|---|---|
| 对象名 | **1–120 字符**，不得为空 | `[代码]` `NodeSchema.name` 的 `min(1).max(120)` |
| 命名稳定性 | **同一部件在不同版本间必须保持同名同层级**。重命名或改变父子关系会导致该部件上的动画、热点、规则在二次上传后需要人工重新指定 | `[规范]` SCHEMA_SPEC §5.3 重映射阶梯：路径 → 名字 → 路径相似度 → 孤儿 |
| 同名兄弟 | **应避免**。glTF 允许同名兄弟，但重映射时会产生「多个同名候选」并要求人工选择 | `[代码]` `indexObjects` 首个命中优先并告警 |
| 空节点 | 无名、且子节点不超过一个的 Group 会被**折叠**，其变换并入子节点 | `[代码]` `isMeaningful` |
| 有意义的节点 | 网格、或有名字的节点、或有多个子节点的节点 | `[代码]` `isMeaningful` |

> **重映射阶梯的含义，用一句话说给商务侧：**
> 部件叫什么、挂在谁下面，决定了客户改一版模型之后，我们之前做的配置能不能自动跟过去。
> 名字全变 = 配置全部需要人工重指。这是可预防的返工，而预防手段就是这一节。

## 5. 材质与贴图

| 项 | 要求 | 来源 |
|---|---|---|
| 材质模型 | **PBR Metallic-Roughness**（glTF 2.0 核心） | `[规范]` MVP_V0 §1.3 v0 不含 EffectComposer 与自定义着色器 |
| 多材质网格 | **不支持**对其应用材质覆盖。一个网格一个材质槽 | `[代码]` `MaterialRegistry.materialFor` 遇多材质网格拒绝并报错 |
| 共享材质 | 允许，且是常态。系统在改写时自动写时复制，改一个部件不会影响共享同一材质的其他部件 | `[代码]` ADR-0011 无条件克隆 |
| 贴图色彩空间 | baseColor / emissive 用 sRGB，其余用线性 | `[代码]` `TEXTURE_SLOT_COLOR_SPACE` |
| 透明 | 允许 alpha blend 与 alpha mask | `[规范]` — |

## 7. 性能验收前提

以下是我方承诺性能表现的**前提条件**。任一不满足，性能表现不作为验收依据：

1. 资产通过第 2 节的全部体量上限（导入报告全绿）；
2. 客户端浏览器**支持 WebGL 2**（Chrome 56+ / Edge 79+ / Firefox 51+ / Safari 15+）；
   > **v0 不支持 WebGL 1**，见 [ADR-0013](adr/0013-v0-不支持-webgl1.md)。这是必须在签约前
   > 与客户确认的一条：旧内核浏览器会看到一个说明页而不是内容。
3. 客户端**已启用硬件加速**且显卡驱动为近期版本；软件渲染下的表现不作为依据；
4. 验收在**目标机器**上进行，使用 [BENCHMARK.md](BENCHMARK.md) 描述的 benchmark 页面出具报告。

### 待回填的性能指标

| 指标 | 目标值 | 状态 |
|---|---|---|
| 平均帧率 | 待定 | `[待实测]` 当前经验阈值 45 fps（黄灯）/ 25 fps（红灯），**尚无目标机器实测** |
| P95 帧时间 | 待定 | `[待实测]` 当前经验阈值 33 ms / 66 ms |
| 首屏加载时间 | 待定 | `[待实测]` 取决于资产体积与网络，需在客户实际网络环境下测 |
| 显存占用 | 待定 | `[待实测]` benchmark 给的是估算值，真实占用取决于驱动内部格式 |

> **这四行留空是刻意的。** 一份带错数字的合同附件，比一份留白的危险得多。
> 拿到目标机器的实测结果后，用 benchmark 页面「复制为 Markdown」的输出直接回填。

## 8. 送检清单（交给交付方的一页）

- [ ] 单个 `.glb`，不引用任何外部文件
- [ ] 三角面数 ≤ 300,000
- [ ] 贴图 ≤ 40 张，单张边长 ≤ 2048 px
- [ ] 材质 ≤ 60 个，PBR Metallic-Roughness
- [ ] 单位为米，Y 轴向上（否则请在交付说明中写明源单位与上方向）
- [ ] 每个需要单独交互的部件**有名字**，且该名字在后续版本中保持不变
- [ ] 同一父节点下没有重名的兄弟节点
- [ ] 原点位于装配体的几何中心或安装基准面附近
