# 载入与启动

> 这一页是写给**现场那个人**的。你拿到的是一个 tar 包，机器不能上网。
> 全程大约 10 分钟。**照着做，卡在哪一步就把那一步的输出发回来。**

## 0 · 先看一眼包里有什么

```
image.tar                  Docker 镜像（装了 Docker 的机器用这个）
site/                      静态文件（只装了 Node 的机器用这个）
serve.mjs                  纯进程部署的服务器
w3-web.service             Linux 开机自启模板
install-windows-task.ps1   Windows 开机自启脚本
manifest.json              版本与文件清单
SHA256SUMS                 校验和
```

**两条路选一条**：机器上有 Docker 走 A，只有 Node 走 B。两条路服务的是同一份站点。

---

## 1 · 先校验（两条路都要做）

拷贝过程中断一次、U 盘掉一位，都会让后面的现象变得没法解释。**先花 30 秒排除它。**

Linux / macOS：

```bash
cd <解开的目录>
sha256sum -c SHA256SUMS
```

Windows PowerShell：

```powershell
cd <解开的目录>
.\load.ps1 -VerifyOnly
```

**每一行都要是 `OK`。** 有任何一行不是，别往下走——重新拷一遍。

---

## A · 有 Docker 的机器

```bash
# 1 载入镜像
docker load -i image.tar

# 2 起起来（8080 换成你要的端口）
docker run -d --name web3d -p 8080:8080 --restart=unless-stopped web3d-deploy:offline

# 3 验证
curl -fsS http://127.0.0.1:8080/healthz     # 应当输出 ok
```

用 podman 的话，把上面三条里的 `docker` 换成 `podman` 即可，其余一个字不用改：

```bash
podman load -i image.tar
podman run -d --name web3d -p 8080:8080 --restart=unless-stopped web3d-deploy:offline
curl -fsS http://127.0.0.1:8080/healthz
```

---

## B · 只有 Node 的机器

```bash
# 1 起起来
node serve.mjs --root=./site --port=8080

# 2 另开一个终端验证
curl -fsS http://127.0.0.1:8080/healthz     # 应当输出 ok
```

看到 `ok` 就说明通了。**Ctrl+C 会停掉它**——要让它开机自启，往下看。

### B-1 · Linux 开机自启

```bash
sudo useradd -r -s /usr/sbin/nologin w3 || true
sudo cp w3-web.service /etc/systemd/system/
sudo $EDITOR /etc/systemd/system/w3-web.service   # 改三个 <> 占位
sudo systemctl daemon-reload
sudo systemctl enable --now w3-web
curl -fsS http://127.0.0.1:8080/healthz
```

三个占位分别是 node 的绝对路径、这个目录的绝对路径、`site/` 的绝对路径。
文件里每一个都写了怎么取。

### B-2 · Windows 开机自启

管理员 PowerShell：

```powershell
.\install-windows-task.ps1 -SiteRoot (Resolve-Path .\site)
Invoke-WebRequest http://127.0.0.1:8080/healthz -UseBasicParsing | Select-Object -Expand Content
```

卸载：`.\install-windows-task.ps1 -Uninstall`

---

## 2 · 怎么算装好了

浏览器打开 `http://<这台机器的地址>:8080/`，应当看到**编辑器**。

再打开 `http://<这台机器的地址>:8080/player/`，应当看到**播放器**。

两个都打开了才算好。只开了第一个的话，发布出来的文件在这台机器上打不开——
而编辑器本身看起来完全正常，这是最容易漏的一种「装好了」。

## 3 · 出问题时

| 现象 | 多半是 |
|---|---|
| `curl: (7) Failed to connect` | 服务没起来，或者端口被别的程序占了。换个端口试试 |
| 页面白屏、控制台报 `Failed to fetch` | `site/vendor/` 没拷全。回第 1 步校验 |
| 页面能开，模型加载不出来 | 同上，多半是 vendor 里的解码器缺了 |
| `/player/` 打开的是编辑器 | 站点目录结构不对，`site/player/index.html` 不在 |
| 端口重启后被占着不放 | 用 `docker rm -f web3d` 或 `systemctl stop w3-web` 先停干净 |

**这台机器全程不需要联网。** 如果你在浏览器控制台里看到任何指向外网的请求，
那是一个缺陷，请把那条 URL 发回来——不是配置问题。
